## Current position

Local task contract/registry, fixed validation executor, strict typecheck, pure payment transition model, idempotency decision contract, provider adapter port/response normalizer/fake, and PostgreSQL persistence design are implemented or documented. Payment graph and evidence labels remain proposed, not provider-validated; evidence labels are not proof. Idempotency is not backed by persistence or atomic concurrency control. No API, database, migration, webhook verifier, ledger, or financial operation exists. OpenCode has not run a coding task and no remote model request was sent. The local registry remains a single-process prototype, not a secure queue or OS sandbox. OpenCode dispatch remains gated by verified provider/cost authorization and safe isolation.
